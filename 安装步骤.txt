========================================================
  ComfyUI 插件（Yunzai）—— 第一次安装步骤
========================================================

【第 0 步】先确认两件事
    1) Yunzai 能正常跑（能收到消息、能回复）
    2) Yunzai 用的 Node 版本 ≥ 18
       在 Yunzai 目录执行：  node -v
       低于 18 的话这个插件跑不起来（用了新的网络接口）


【第 1 步】把插件文件夹放进去
    把整个 comfyui-plugin 文件夹复制到 Yunzai 的 plugins 目录下，变成：

        <你的Yunzai目录>/plugins/comfyui-plugin/
            index.js
            apps/
            components/
            config/
            utils/
            model/
            README.md

    文件夹名字随便改都行（代码会自己找路径），
    但为了跟说明对得上，建议就叫 comfyui-plugin。

    不需要 npm install —— axios 和 yaml 这两依赖 Yunzai 本体已经带了。


【第 2 步】重启 Yunzai
    重启后看日志，应该出现：
        - 正在载入 ComfyUI-PLUGIN
        - ComfyUI-PLUGIN 载入成功
    如果这两个没出现，说明文件夹位置不对或者 Node 版本太低。

    首次启动会自动生成：
        plugins/comfyui-plugin/config/config/config.yaml
        （从 config_default.yaml 复制来的，是你要改的那个文件）


【第 3 步】填 ComfyUI 地址
    用记事本打开 plugins/comfyui-plugin/config/config/config.yaml，
    找到这一行，按你的情况改：

        api_list:
          - baseurl: "http://127.0.0.1:8188"

    怎么填：
      * Yunzai 和 ComfyUI 在同一台电脑
            http://127.0.0.1:8188
      * Yunzai 在局域网另一台机器/手机上（同一个路由器）
            http://192.168.1.100:8188         （换成 ComfyUI 那台机的 IP）
      * Yunzai 在云服务器上（两台机器不在一个网里）
            用之前那套隧道地址，并且要填账号密码：
                api_list:
                  - baseurl: "https://xxxx.trycloudflare.com"
                    username: "comfy"
                    password: "你的密码"

    保存文件。不用重启 Yunzai（每次请求都会重新读配置）。

    ⚠ 如果 Yunzai 不在本机，ComfyUI 必须带 --listen 0.0.0.0 启动，
      否则别的机器连不上。（本机那套「后台启动ComfyUI.bat」已经带了）

    【如果你装了锅巴插件】
      可以跳过手动编辑，改在网页上填：
        云崽后台（#锅巴登录）→ 左侧找到「ComfyUI 绘图」
        里面有 5 组共 41 项，其中「ComfyUI 接口」第 1 个地址就是上面那个 baseurl；
        「工作流与运行」里的默认工作流是下拉框，会自动列出 config/workflows/ 里的 json。
      改完点保存即可，效果和手改 yaml 完全一样。


【第 4 步】自检（推荐，能省很多排查时间）
    在插件目录执行：

        node _selftest.mjs

    会真的让 ComfyUI 出一张图并保存到 resources/tmp/。
    看到 ✅ 成功 + 图片已保存，就说明配置、网络、工作流全对。

    也可以用指定的提示词和工作流测：
        node _selftest.mjs "一只戴帽子的猫" z-image-turbo
        node _selftest.mjs "把背景换成雪天" qwen-image-edit-2509 --image "D:\测试.png"


【第 5 步】在群里试
    #绘图 一只戴帽子的猫
    #绘图 一只猫 --steps 8 --size 1024x1024
    #绘图 一只猫 --ratio 16:9      （画面比例：1:1 / 16:9 / 9:16 / 21:9 / 4:3 / 3:4 / 3:2 / 2:3）
    #重绘                        （复用上一次的提示词，再画一张）
    #上次提示词                   （看上次用的是什么提示词）
    #查看默认参数
    #工作流列表

    （引用一张图）#改图 把背景换成雪天

    上面这些指令的回复都会画成图片卡片。
    #工作流列表 里每个工作流前面有序号，记住序号就能直接切换：
        #用工作流 5                    把第 5 个设成默认（仅主人）
        #绘图 一只猫 --workflow 5      只这一次用第 5 个


【第 6 步】限制谁能用（可选；要限制就做这一步）
    #开启绘图白名单              打开总开关（仅主人）
    #添加绘图白名单 本群          把当前群加进名单（在哪个群发就加哪个群）
    #添加绘图白名单 @某人         把某人加进私聊名单
    #绘图白名单                  随时看现在允许哪些群 / 人

    没进名单的群/人发绘图指令会被拦下，并收到一句提示（提示里带群号，方便你复制来加）。
    机器人主人始终放行，不会把自己关在外面。

    默认是「完全不回复」（安静）：名单外的人发指令，机器人像没收到一样，
    但只会"不管这条消息"，别的插件照常工作、不受影响（拦截时返回 false）。
    想看到底哪个群被拦、要群号时：
        #绘图白名单 提示          被拦时回一句带群号的提示
        #绘图白名单 静默          改回完全不回复


========================================================
  出问题看这里
========================================================

现象：载入插件错误 / 日志里没有“载入成功”
    检查文件夹是不是直接放在 plugins 下（不要多套一层）
    检查 node -v 是否 ≥ 18

现象：回复“还没有配置 ComfyUI 接口”
    config/config/config.yaml 里 api_list 是空的，或者缩进写错了
    可以照着 config_default.yaml 的格式抄

现象：回复“连不上 ComfyUI”
    1) ComfyUI 是不是在运行（浏览器打开 http://127.0.0.1:8188 试试）
    2) 地址写对没有；跨机器的话要用 IP 不是 127.0.0.1
    3) ComfyUI 启动有没有带 --listen 0.0.0.0
    4) 防火墙：ComfyUI 的 python.exe 需要放行（之前已经放行过）

现象：回复“找不到工作流模板”
    看 config/workflows/ 里有没有 json；文件名不要带 .json 后缀
    用 #工作流列表 看现有名字

现象：帮助/列表回复的是文字（合并转发）而不是图片卡片
    说明渲染器出了点问题，插件会自动降级成文字，功能不受影响。
    想看原因：pm2 logs TRSS-Yunzai --lines 100 | grep 卡片渲染失败
    常见原因是 lib/puppeteer/puppeteer.js 不存在，或者没装 Chromium。

现象：回复“接口返回 401”
    隧道那套闸门要账号密码，config.yaml 里的 username/password 填上

现象：一直排队不动
    用 #绘画队列 看前面还有多少任务。ComfyUI 是单队列串行，
    前面在跑你的批量任务时，群里这条就得等。

现象：出图很慢
    第一次跑某个模型要加载权重（十几秒到一分钟），第二次就快了。
    另外工作流里的步数、分辨率直接决定时间。
